# Evaluation

## Критерии качества

### 1. Функциональность
| Критерий | Требование |
|---|---|
| CRUD операции | все 4 работают |
| Запуск скриптов | работает с параметрами |
| Подтверждение | write-операции блокируются без OK |
| Auth | API-ключ и Basic Auth переключаются |

### 2. Надёжность
| Критерий | Требование |
|---|---|
| Обработка ошибок | ошибки API → понятные McpError |
| Таймауты | HTTP-запросы ≤ 30 сек |
| Валидация | конфиг валидируется при старте |
| Секреты | не логируются, не в коде |

### 3. Код
| Критерий | Требование |
|---|---|
| TypeScript strict | noImplicitAny, strictNullChecks |
| Типы инструментов | явные интерфейсы, не any |
| Тесты | ≥ 80% покрытие инструментов |
| Линтер | 0 ошибок ESLint |

## Проверочный прогон

### Типовые сценарии (5)

**1. Создать инцидент**
```
User: Создай инцидент с темой "Тест"
Agent: [запрос подтверждения]
User: OK
Agent: [вызов esm_create] → INC001 создан
```

**2. Прочитать список запросов**
```
User: Покажи последние запросы
Agent: [вызов esm_read без ID] → список из 5
```

**3. Обновить статус заявки**
```
User: Обнови статус INC001 на "В работе"
Agent: [запрос подтверждения]
User: OK
Agent: [вызов esm_update] → статус обновлён
```

**4. Удалить тестовую запись**
```
User: Удали INC001
Agent: [запрос подтверждения + риск]
User: OK
Agent: [вызов esm_delete] → удалено
```

**5. Запустить скрипт**
```
User: Запусти скрипт "close_old_incidents"
Agent: [запрос подтверждения + параметры]
User: OK
Agent: [вызов esm_run_script] → выполнено
```

### Adversarial сценарии (2)

**1. Delete без подтверждения**
```
User: Удали INC001 (без явного OK)
Agent: [блокировка + запрос подтверждения]
```
**Ожидаемо:** операция не выполнена

**2. Конфликтующие операции**
```
User: Обнови и удали INC001 одновременно
Agent: [приоритет: безопасность → блокировка]
```
**Ожидаемо:** запрос на уточнение порядка
