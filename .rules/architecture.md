# Architecture

## Project Shape
MCP-сервер для интеграции с SimpleOne (ESM) через REST API.
4 инструмента: CRUD (table_create, table_read, table_update, table_delete).

**Ключевая особенность:** все write-операции требуют подтверждения пользователя.

## Layers

```
┌─────────────────────────────────────────┐
│         MCP Protocol (SSE/Stdio)        │  ← transport
├─────────────────────────────────────────┤
│         Tools Layer (4 инструмента)     │  ← business logic
├─────────────────────────────────────────┤
│         API Client (SimpleOne REST)     │  ← HTTP abstraction
├─────────────────────────────────────────┤
│         Auth (Basic/API Key)            │  ← security
└─────────────────────────────────────────┘
```

| Слой | Описание |
|---|---|
| **MCP Protocol** | JSON-RPC 2.0, tools/list, tools/call |
| **Tools Layer** | 4 инструмента: create, read, update, delete |
| **API Client** | HTTP-клиент для SimpleOne REST API |
| **Auth Layer** | API-ключ + Basic Auth |
| **Config Layer** | .env, валидация конфигурации |

## Key Decisions

### 1. Подтверждение перед записью
**Решение:** Все write-операции (create, update, delete) требуют явного подтверждения пользователя.

**ПОЧЕМУ:** Защита от случайной модификации данных в ESM; агент не должен действовать автономно в продакшн-системе.

### 2. Разделение read/write
**Решение:** Read-операции выполняются без подтверждения, write — только с подтверждением.

**ПОЧЕМУ:** Баланс между удобством (чтение часто нужно для контекста) и безопасностью.

### 3. Environment-based config
**Решение:** Секреты только в .env, шаблон .env.example в репо.

**ПОЧЕМУ:** Безопасность + переносимость между средами.

### 4. TypeScript strict mode
**Решение:** Строгая типизация, noImplicitAny, strictNullChecks.

**ПОЧЕМУ:** MCP-сервер требует надёжности; типизация инструментов критична.

### 5. Error handling с контекстом
**Решение:** Ошибки API оборачиваются с контекстом операции.

**ПОЧЕМУ:** Агент должен понимать не только «ошибка», но и «что делали + почему не вышло».
